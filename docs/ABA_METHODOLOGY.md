# ABA-методология в Talentia — реализация в коде

Этот документ описывает, как принципы ABA (Applied Behavior Analysis) реально
реализованы в `talentia-mobile`, по состоянию после прохода фиксов от
2026-08-15/16 (см. историю коммитов, сообщения `1.1`–`4.5`). Он существует
потому, что `talentia-mobile/curricula/*-aba.md` — это автогенерированные
экспорты контента (списки диалогов/заданий), а не спецификация дизайна:
там нигде не описаны иерархия подсказок, критерий mastery, структура DTT
или график поощрений. Единственное место, где методология была
задокументирована раньше — комментарий в коде
(`app/lesson/[lessonId].tsx`), и он не полностью совпадал с реализацией до
фиксов. Этот файл — источник правды на уровне "что происходит и почему",
код — источник правды на уровне "как именно"; при расхождении в будущем
доверяй коду и обнови этот файл.

## 1. Иерархия подсказок (prompting hierarchy)

Модель — "least-to-most", 3 уровня, отслеживается через `promptLevel`
(`0 | 1 | 2`) в `app/lesson/[lessonId].tsx`:

- **Level 0 (independent)** — ребёнок отвечает сам, без подсказок.
- **Level 1 (visual/text prompt)** — после первой ошибки НА ЭТОМ задании:
  правильный вариант подсвечивается (`isVisualTarget`), плюс текстовая
  подсказка (`hintText`). В ABA-режиме подсказка генерируется через AI
  (`getHint`, AI-proxy запрос); в стандартном режиме — статичная строка
  `lesson.standardHintLevel1` (без AI-вызова, чтобы не размножать нагрузку
  на прокси на всю базу пользователей).
- **Level 2 (restricted choice)** — после второй ошибки: неверные варианты
  блокируются (`isDisabledByPrompt`), для `sorting`/`routine_chain`
  подсвечивается верная группа/следующий шаг, для `input` показывается
  первая буква ответа (`lesson.inputFirstLetterHint`).

Эскалация **per-trial** (за одно задание), не накопительная за весь урок:
счётчик `taskMistakeCount` сбрасывается в `resetForNextTask()` при переходе
к новому заданию. Работает в **обоих режимах** — раньше уровни 1/2 были
доступны только при `useAbaPedagogy`, стандартный режим не получал
эскалацию вообще.

**Response window**: если ребёнок не начал отвечать в течение
возраст-зависимого окна (`responseWindowMsForAgeBand`: 15с для 5-6 лет,
18с для 7, 20с для 8+), Level 1 срабатывает автоматически, даже без
ошибки — это покрывает случай "нет ответа", а не только "неверный ответ".
Терапевт-ведомые типы заданий (`vocal_imitation`, `word_repetition`,
`volume_control`, `action_instruction`) исключены — их оценивает взрослый
вживую, автоматический response window для них не применяется.

## 2. Mastery criteria

`getLessonStatus()` (`src/store/progressStore.ts`) не разблокирует
следующий урок, пока предыдущий не пройден с рейтингом
`>= masteryMinStars` (по умолчанию 2 звезды из 3, т.е. ≤2 ошибки за урок —
грубый эквивалент "≥80% верно, иначе на повторение"). Порог настраиваемый
через `setMasteryMinStars`, единого UI в настройках пока нет.

Уже пройденные уроки никогда не блокируются задним числом, если
предыдущий урок позже переигран с худшим результатом — гейт влияет только
на НОВую разблокировку.

## 3. Discrete Trial Teaching (DTT)

Для каждого задания: **SD** (`questionKey`, озвучивается через TTS),
**response window** (см. выше), **consequence** (визуальная/гаптическая/
голосовая обратная связь сразу после ответа). Единообразно для всех типов
заданий.

## 4. Reinforcement schedule (график поощрений)

- **Похвала за ответ** (ABA-режим): полноэкранный баннер после каждого
  верного ответа, случайная фраза из пула (без повтора подряд).
  Частота настраивается по возрасту — `reinforcementRateForAgeBand`:
  100% для 5-6 лет, снижается до 60% к 9-10 (баннер иногда пропускается,
  ребёнок переходит к следующему заданию сразу; гаптика при этом
  срабатывает всегда).
- **Токен-экономика** (ABA-режим, пазл из `ABA_PUZZLE_PIECE_COUNT` частей):
  по умолчанию (`abaTokenRewardSchedule: 'per_lesson'`) начисляется одной
  суммой в конце урока (по звёздам). Есть опция `'per_trial'` — по 1 токену
  за каждый верный ответ сразу, без ожидания конца урока; тогда финальный
  экран пазла/токенов пропускается (токены уже начислены).
- **Bonus XP**: ~10% шанс (`LESSON_BONUS_XP_CHANCE`) получить +5 XP сверху
  обычной награды при завершении урока — единственный по-настоящему
  вариативный (variable-ratio) элемент поощрения; всё остальное
  детерминировано по результату.
- **Экран награды**: заголовок и иконка XP выбираются случайно из
  пула (4 варианта каждый); реакция Тали (`energetic`/`friendly`/`idle`)
  зависит от количества заработанных звёзд, а не всегда одна и та же.

## Известные ограничения (не закрыты этим документом)

- Порог `masteryMinStars` и график `abaTokenRewardSchedule` — настраиваемые
  параметры в сторах, но без экрана в Settings для родителя/специалиста.
- ABA-упрощённые тексты (`abaTextOverrides.*.json`) полноценно переведены
  только для русского; для EN/KY закрыта только часть ключей (см. коммиты
  `1.4`/`1.5`/`2.4`/`2.5`) — остальное см. в итоговой сводке аудита.
- Реакции Тали вне экрана награды (диалоги, FAB, модалка) остаются
  фиксированными — нет состояния "помнит предыдущие сессии".
