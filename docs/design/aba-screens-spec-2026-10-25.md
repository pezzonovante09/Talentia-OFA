## 2. Экран обязан

4. **Тайминги.** `endedAt` предъявления — конец аудио SD/подсказки (визуальная — `max(конец аудио, старт
   визуала)`); от него окно и латентность. Первое окно `promptDelayMs ?? responseWindowMs`, дальше
   `responseWindowMs` после каждого предъявления, включая L3; следующее — не раньше конца окна. Эскалация только
   `nextEscalation(…, promptLadder(target))`, ≤ 3 предъявлений. `allowEscalation === false` — подсказок нет.
   `pauseBeforeMs` — нейтральная пауза 5 с. `say`: окно 6000 мс на 5–6; L1 — подсветка и повтор SD (`verbal` —
   SD с паузой), L2 — `partialModelKeys` по порядку, L3 — полная модель.
5. **Касания и панель.** `identify`: касания до конца SD игнорируются, пишутся как `activity`; одна карточка чаще
   150 мс — одно касание; засчитывается первое касание активной плиты; писать `chosenCardId`, `tapCount`,
   `fieldSizeAtResponse`; тап по неактивной плите (L3) — без записи; тап по метке = по плите (временно, вопрос 8
   методисту). `match`: варианты неактивны до касания образца; 5000 мс (`MATCH_OBSERVING_MS`) без касания —
   предъявление L1 приложения со `startedAt` = истечение и `observingPrompted: true` (после него `independent`
   невозможен); ещё 5000 мс — `no_response`; окно выбора 5000 мс от касания образца, `observingLatencyMs`.
   Касание поля ставит панель взрослого в очередь на 400 мс от первого тапа; `respondedAt` — касание кнопки;
   побеждает первая кнопка; «Отказ» и «Сопротивляется» не блокируются и снимают отложенную отметку; очередь
   сбрасывается на переходе фазы; нажатие во время аудио — к P0, во время подсказки — к ней. «Была подсказка» —
   предъявление `by: 'adult'` внутри окна текущего, потом своё окно. «Почти» — только при `scoredBy === 'adult'`.
   Карточка «перерыв» — `child_break` с `respondedAt`; вне пробы не принимается (№106).
6. **Состояние.** Только состояние из `nextStep` (поле и `seed`); после выкладки поля — `saveAbaSessionStep`.
   `seed` для `promptVisualFor` — от начала пробы. `resumeAbaSession` при каждом возврате фокуса и после
   `AbaBoardConflictError`, затем `nextStep`; `recordTrial` повторяется с тем же входом без второго жетона.
   `AbaConsentRequiredError` / `AbaPausedError` — спокойный конец; ни ошибки, ни имена ABA-экранов в Sentry и
   телеметрию не уходят.
7. **Подкрепление.** Сначала `recordAbaTrial`, потом последствие, ≤ ~1 с от `respondedAt`; показанный и не
   записанный жетон — отъём. `token_praise` — жетон на доску со звуком; `praise` — только голос; `neutral` — без
   «неверно», дальше; `listened` — «Tali послушал». `praiseAttentionBeforeSd` — похвала до SD. Обмен — только
   `canExchange` / `exchanged > 0`; доступ кончает приложение по `durationMs`.
8. **Итог.** В `finishAbaSession`: `pastSessions` (`pastSessionsOfTarget`, пусто — `{}`), `signalHistory`,
   `extra.routineExchangeInWindow` (после последнего возобновления — обязательно и без рутин); `ioa: undefined`.
   id сессии и проб — UUIDv4 из случайных байт (генератор — до первого экрана). `day` — локальная дата.

## Журнал пробы `match` (`aba-pedagogy-specialist` 2026-10-27)

**`endedAt` у предъявления `match` = max(конец аудио или визуала предъявления, касание образца).** Не коснулись
образца — конец аудио SD (у L1 — конец его сигнала). `promptDelayMs` тикает от касания образца: варианты становятся
SD для выбора только после него, иначе при задержке 1000 мс L1 приходила бы раньше, чем выбрать вообще можно.
Касание образца во время аудио SD — `observingLatencyMs = 0`, варианты активны с конца аудио. Таймер наблюдения
(5000) — от конца SD, в домене это не окно. `latencyMs` — от касания образца до выбора; от конца SD до выбора =
`observingLatencyMs + latencyMs`.

Сценарии (t 0 — начало SD, аудио SD до 1,5, d = 2000, окно 5000; `уровень [startedAt→endedAt] windowMs outcome @respondedAt`):

| | presentationLog | поля пробы | итог |
|---|---|---|---|
| а | L0 [0→2,5] 2000 correct @4,0, activity | obsLat 1000, chosen = образец, tap 2 | independent |
| б | L0 [0→2,5] 2000 none; L1 [4,5→5,3] 5000 correct @6,0 | obsLat 1000 | prompted L1; L1 не раньше 2,5 + d |
| в | L0 [0→1,5] 2000 none; L1 [6,5→8,0] 5000 correct @9,2 (8,0 — касание образца) | `observingPrompted`, obsLat 6500 | prompted L1 |
| г | L0 [0→1,5] 2000 none; L1 [6,5→7,3] 5000 none; закрыта 12,3 | `observingPrompted`, obsLat null | no_response L1 |
| д | L0 [0→2,5] 2000 incorrect @3,4 | chosen = дистрактор | incorrect; обучение — закрыта, дальше коррекция очередью домена |
| е | (L1+) L0 none; L1 [4,5→5,3] none; adult L1 [6,0→6,0] 5000 correct @6,6 | — | prompted, `adultUnplannedPrompt`; **на L0 не пишется** (см. ниже) |
| ж | текущее: refusal **без** `respondedAt` | — | interrupted / assent |
| з | текущее: child_break, `respondedAt` = касание карточки, ≤ endedAt + window | — | interrupted / child_break |
| и | поле 2: L0 → L1 → L3 (L2 нет) | — | — |

Измерительные пробы: L1 наблюдения нет (`allowEscalation = false`), не коснулись за 5000 — no_response. Старт L1+:
отдельный L1 наблюдения не записывается, не коснулись за 5000 — none, дальше `nextEscalation`. Время — один
монотонный источник.

**Где мешает домен (заморожен №134):**
1. «Была подсказка» на L0 отклоняет `trialInvariantErrors` (`abaPrompting.ts`) — не применять проверку задержки при
   `adultUnplannedPrompt`. До правки такую пробу не писать и предъявить заново.
2. Карточка «перерыв» в пробеле наблюдения (после конца SD + d, до 5000, образца не коснулись) — «ответ после окна»;
   до правки — без `respondedAt`. Правка: `observedAt?` у `AbaPresentation` для `match`.
3. **Блокер:** `correctionLevel` не учитывает лестницу — при поле 2 коррекция стартует с L2, `promptVisualFor` бросает.
   Правка: округлять вверх до уровня лестницы.
4. Пробы с `observingPrompted` идут как «ждал подсказку» — растёт задержка и ложный `prompt_dependent`; исключить их
   из этих расчётов.
