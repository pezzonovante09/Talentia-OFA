## Общий вывод в шести строках

1. **Ядро правильное, трогать не надо.** Сужение → показ → обязательный тап; разобранный пример с короткой формой при повторе; Лейтнер по навыку с одним шагом за урок; в ABA — жетон только на стартовом уровне, конец сессии на успехе, реакция наблюдения в `match`. Все три агента независимо назвали это тем, что «точно оставить».
2. **Три вещи обещают и не выполняют — их видно родителю.** Узел «повторение» на карте (Tali указывает на кнопку, которая ничего не открывает), «Освоено» в отчёте (недостижимо по построению), «даётся тяжело» (загорается после безошибочного первого урока).
3. **Лейтнер на 5–6 при реальном темпе не доводит ни один навык до коробки 4.** Место под повторение одно (кап 5 − 4 задания), его всегда забирает самая младшая коробка, спираль следующего урока отодвигает срок, не двигая коробку. Лечится не капом, а сессией узла «повторение» — домен для неё готов.
4. **ABA: процедура для `match` родителю по силам** (две кнопки — «Была подсказка», «Отказ»; всё остальное считает приложение), но родитель **не видит никакого прогресса**, а линейная лестница целей оставляет одну обучаемую цель — без второй цели нет блока B и перерыва по расписанию. Плейсмент сверху вниз написан и не включён.
5. **Домен ABA без экранов: достраивать только `identify`** (после аудио). Рутины, `say`, `do_action`, IOA, параметры специалиста — заморозить до живого методиста: 8 из 10 заданных ему вопросов про рутины, строить экраны по неподтверждённым ответам — переделывать дважды. `voice_volume` — убрать (микрофон без функции).
6. **Найден один настоящий дефект**: выход из урока и возврат в фазе «после показа» или «после верного ответа» роняет урок исключением домена (подтверждено по коду, на устройстве не воспроизводилось).
