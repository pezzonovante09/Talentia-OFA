CREATE FUNCTION public.children_id_not_pseudonym() RETURNS trigger LANGUAGE plpgsql SECURITY DEFINER SET search_path = '' AS $$
BEGIN
  IF EXISTS (SELECT 1 FROM public.consent_events WHERE child_id = NEW.id AND child_pseudonymized_at IS NOT NULL)
     OR EXISTS (SELECT 1 FROM public.child_access_log WHERE child_id = NEW.id AND child_pseudonymized_at IS NOT NULL) THEN
    RAISE EXCEPTION 'child id taken' USING ERRCODE = '42501';
  END IF;
  RETURN NEW;
END $$;
CREATE TRIGGER children_id_not_pseudonym BEFORE INSERT ON public.children
  FOR EACH ROW EXECUTE FUNCTION public.children_id_not_pseudonym();
REVOKE ALL ON FUNCTION public.children_id_not_pseudonym() FROM PUBLIC, anon, authenticated;

## 4. Р3 — доска жетонов при пересечении сессии и прогона рутины (открыто, 2026-10-11)

Блокер методиста при ревью Р3 (`b292837`): сессия и прогон рутины переживают сворачивание и
пересекаются (снимки `abaSessionInProgress` и `abaRoutineRunInProgress`); каждая держит доску
снимком со своего старта. Сбои: рутина показывает доску без жетонов свёрнутой сессии; двойной
обмен одних и тех же жетонов; последняя фиксация затирает доску другой. Состояния целей уже
починены (сессия возвращает только свои цели, `commitAbaSession` сливает с текущей картой).

**Спецификация `backend-auditor` — «живая доска»:**

1. `abaBoard` — единственный источник: `{ earned, nonContingent, rev }` (`rev` по умолчанию 0);
   в `AbaSessionState` — `boardRev` со старта. Миграция не нужна (ключ уже в ABA-состоянии).
2. Сессия пишет доску сразу: `recordAbaTrial` и `commitAbaSession` в той же транзакции пишут
   `abaBoard` с `rev + 1`; новый `saveAbaSessionStep` — для шагов без пробы (обмен в `finishBreak`).
3. Проверка версии при каждой записи доски сессией: `abaBoard.rev !== state.boardRev` →
   `AbaBoardConflictError`, откат, не пишется ничего; экран возобновляет и повторяет `recordTrial`.
4. `resumeAbaSession(db, childId)` — единственный путь продолжить сессию (и при фокусе экрана):
   доска — размер из снимка, `earned` / `nonContingent` / `rev` из `abaBoard`; собственные счётчики
   сессии не трогаются.
5. Рутина: `board` убрать из `RoutineRunInput` / `RoutineRunState`, добавить `band`;
   `finishRoutineRun` доску не трогает, возвращает заявку `claim = { kind, tokens, nonContingent }`;
   чистая `settleRoutineBoard(board, claim, { pool, history, seed })` → `{ board, token, exchange? }`
   (`participationAward` — по живой доске); `commitRoutineRun` в одной транзакции читает
   `abaBoard`, `tokenTraining`, историю подкрепителей, размер — `workingBoardSize`, пишет запись
   с настоящими `token` / `exchanged` и доску с `rev + 1`; возвращает `RoutineCommitOutcome` —
   экран показывает обмен по нему.
6. Обмен без выбора (приложение убили после фиксации): запись с `exchanged > 0` без выбора в
   журнале п. 8 → при следующем открытии выбор предлагается снова, варианты из той же затравки.
7. Размер доски меняется между процедурами (ступень растёт и падает): рутина берёт размер по
   текущему `tokenTraining`; `earned >= size` → обмен всех жетонов.
8. История подкрепителей — только дописывание: таблица `aba_reinforcer_choices(child_id, seq,
   chosen_at, source 'session' | 'routine', source_id, reinforcer_id, chosen_by)`, запись в момент
   выбора (сессия — `chooseReinforcer`, рутина — `recordRoutineExchangeChoice`), порядок по
   `chosen_at`, затем `seq`; читать в той же транзакции, где считаются варианты. Новая миграция
   (`gated`, `retained`, триггер согласия, удаление при отзыве) — скилл `db-migration`.
   `aba_sessions.reinforcerId = ''` без выбора — в историю не брать.
9. Тесты (`qa-engineer`), инвариант: `abaBoard.earned` на старте + жетоны проб и участия сессии +
   жетоны рутин − обмены сессии − `exchanged` рутин = итоговый `abaBoard.earned`. Т1 обед без
   обменов; Т2 двойной обмен (размер 3, доска 2); Т3 обратный порядок; Т4 рутина заполняет доску
