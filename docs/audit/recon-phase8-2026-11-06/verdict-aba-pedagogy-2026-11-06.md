## 1. Решения до кода

- **а1 — иначе (уточнение, домен не трогается).** Не «кадр L0», а **стартовый уровень пробы**: `trialStep` (866–875)
  строит шаг из `startPromptLevel` цели (по №165/№167 может быть L1). Внутрипробное усиление L0→L1→L2 живёт в
  `matchTrialRun` и при сворачивании теряется — и должно: возобновить на L2 значило бы дать подсказку без новой
  возможности ответить самостоятельно. Окно ответа и задержка — заново от нового SD. Ц2.11 поправить: «кадр стартового
  уровня пробы, не выше».
- **а2 — нужна.** Прецедент в домене: после перерыва по карточке `handleInterruption` (1439–1453) ставит
  высоковероятную пробу *другой* освоенной цели перед повтором. После 2–30 мин то же. Цель: `highPTrial` из
  `highPTargetIds`, исключая цель головной пробы; нет других освоенных — не вставлять. Место: в `resumeAbaSession` при
  `rechoose` — перед первой пробой очереди, после ведущих `break`/`access`/`block_end`. Дедупликация: если первая проба
  уже `kind: 'high_p'` — вторую не ставить. Без `requeuedFromTrialId` (`inGuardWindow` не открывается). При
  `reinforcerId === null` — не вставлять. При `awayMs = 0` (повтор после конфликта) — не вставлять.
- **а3 — как предложено.** `no_choice` в «Сам» при повторном выборе → `abandoned` верно; жетоны остаются на живой доске.
- **а4 — как предложено.** Повтор плашки = второе подкрепление одного ответа.
- **а5 — как в домене: выбор при возврате, до конца перерыва; затем «Вернуться»; обмен — в `finishBreak`.** Иначе
  `reinforcerStale` подавит обмен (`breakExchanges` 1202) и полная доска ждёт следующего перерыва (№169). Срок по
  бездействию и приглашение — от момента возврата. Обучающий перерыв — возврат взрослым (№169 п. 3). Тихая пауза
  истекла в фоне — закрыть как `until`. **Утечка времени — правка домена:** `finishBreak(state, now, endedAt = now)`:
  событие `break.endedAt = endedAt` (`until`), `pausedMs += now − breakStartedAt`.
- **а6 — как предложено.** Невиденный обмен = невыданное подкрепление; показать заново. Удержание `fromFullBoard` —
  вопрос вида.
- **а7 — иначе: (а) при возврате до T, (б) после T.** Возврат до T — два отрезка `[сцена, leftAt]` и `[возврат, T]`;
  после T — один `[сцена, leftAt]`, остаток не пишется. Вариант (в) отвергнут. `finishAccess(state, now = возврат,
  scene | scene[])` — по событию `access` на отрезок, `pausedMs` через `now` (1281) — утечки нет. Начало сцены в
  снимке не хранить: приближение «не раньше `accessStartedAt`» (погрешность ≤ 3 с) допустимо.
- **а8 — иначе (частично).** `wait`/`pairing_token` — как предложено. Но шаги `exchange`/`access` хвоста: обмен уже
  снял жетоны в `commitAbaSession`, «Закончили» без доступа — отъём. Тёплый возврат при `awayMs < AWAY_RECHOOSE_MS`:
  уход на `exchange` до начала сцены — доступ с начала; уход на `access` — правило а7. ≥ 2 мин или холодный старт —
  «Закончили», в записи хвоста `leftAtStep` и фактические отрезки. Второго жетона цикла — никогда.
- **а9 — как предложено; «дозвать оставшиеся» предпочтительнее, если дёшево.**
- **в1 — как предложено.** Закрытие по действию родителя, без экрана конца ребёнку.

  показан. Условия: нейтральный конец показывает **живую** доску; без грустных сигналов; наблюдателей предупредить,
  что сессия, закрытая ошибкой, может не содержать последней пробы.
- **е1 — иначе: одна новая причина `'app_error'` для обоих режимов.** Не участвует в ступени, без обмена в конце, без
  цикла сопряжения, различима. Запасной вариант при отказе владельца — `adult_stopped`/`app_backgrounded` с пометкой
  неточности в ABA.md «Данные». Guard `st.current === null` → без записи — верно.
- **е3 — как предложено, с двумя дополнениями.** `accessScene` — массив отрезков (0..2), добавить `leftAt`

  `tail === null` → «неизвестно», не «выдано».

## Правки домена (точечная разморозка №134)

1. `types/aba.ts` `AbaSessionEndReason`: `+ 'app_backgrounded'`, `+ 'app_error'`.
2. `abaSession.ts` `stopSession`: тип `reason` расширить; поведение не меняется.
3. `abaTokenTraining.ts` `applyStageSession`: `adult_stopped | app_error` → `return t`; `app_backgrounded` при
   `config === 'alone'` — как `abandoned`, при `with_adult` → `return t` (нужен `config` в `StageSession`).
4. `abaSession.ts` `resumeAbaSession`: при `rechoose` — одна высоковероятная проба другой освоенной цели (правила а2).
5. `abaSession.ts` `finishBreak(state, now, endedAt = now)`.
6. `abaSession.ts` `finishAccess(state, now, scene | scene[])`.
7. `types/aba.ts` `AbaSessionTail = { sessionId; accessScene: Scene[]; pairingTokenAt: string | null;
   leftAtStep: TailStep['kind'] | null; leftAt: string | null; completed }`.
8. JSDoc `needsPairingCycle`, `EXCHANGE_AT_END`, `awayOutcome`; перечисления `endReason` в `abaBreakCard.ts`,
   `purge.ts`, экспорт — обе причины. `awayOutcome` без `sameDay` не трогать.

## Обязательные тесты домена

- `stopSession(…, 'app_backgrounded' | 'app_error', leftAt)`: перерыв/доступ закрыты моментом ухода.
- `finishAbaSession` с обеими причинами: нет обмена при полной доске, нет `pairing`; `it.each` в `abaFinishStale.test.ts`.
- `applyStageSession`: `app_backgrounded` со взрослым — `atStage` не растёт; в «Сам» — блокирует рост, `falls`;
  `app_error` — не участвует.
- `resumeAbaSession`: при `rechoose` ровно одна высоковероятная другой цели; не вставляется при `same_trial`,
  `awayMs = 0`, `reinforcerId === null`, при `high_p` в голове, без других освоенных; `inGuardWindow` не открывается.
- `finishBreak(now, until)`: `break.endedAt = until`, `workedMs` без фона; без третьего аргумента — прежнее поведение.
- `finishAccess` с двумя отрезками — два события; один до `leftAt` после T; старая сигнатура — прежнее поведение.
- Цепочка «снимок → `resumeAbaSession(0)` → `stopSession(reason, leftAt)` → `finishAbaSession(leftAt)`»: `endedAt = leftAt`.
