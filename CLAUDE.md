# CLAUDE.md — Talentia

Инструкции для Claude Code по работе с этим репозиторием.

## О проекте

Talentia — образовательное приложение для детей 5–10 лет (возрастные полосы `5-6`, `7`, `8`, `9-10`)
на русском, английском и кыргызском, с отдельным ABA-режимом и ИИ-компаньоном Tali.

**Идёт пересборка с нуля** — вход `AUDIT.md`, затем «С чего начать новой сессии» в `REBUILD.md`.
Прежнее приложение удалено из кода 2026-10-01 (не было опубликовано; код — в истории git до
`38f57a7`). Экранов в коде сейчас нет.

| Часть | Путь | Стек |
|---|---|---|
| Мобильное приложение | `talentia-mobile/` | Expo SDK 54, RN 0.81, React 19, expo-router, expo-sqlite |
| AI-прокси | `talentia-ai-proxy-next/` | Next.js 16 на Vercel: `/api/v2/tali`, `/api/account/delete`, `/api/ping` |
| База | `supabase/migrations/` | Supabase: PostgreSQL + RLS; тесты в PGlite (`npm run test:db`) |

Подробности: [`ARCHITECTURE.md`](ARCHITECTURE.md), [`README.md`](README.md).

## Команды

```bash
npm run install:all     # установить зависимости обоих пакетов
npm run lint            # ESLint в обоих пакетах

npm run build:api       # сборка прокси

npm run dev:api         # прокси локально
```

## Ворота по риску (№121–123)

| Ворота | Что закрыто | Как открыть |
|---|---|---|
| Прототип | ничего — экраны и контент пишутся сразу; только локально, без облака и ИИ, дети — при взрослом | — |
| «Данные» | любой выход в сеть из `src/` и `app/` — ESLint `offlineRules` в `talentia-mobile/eslint.config.js` (`eslint-disable` не действует) | раунд `child-privacy-compliance` + `backend-auditor` с 0 блокеров, запись `scope: "data"` в `.claude/audit-gate.json`; запрет снимается для одного адаптера `src/services/remote/**` |
| «Выпуск» | сабмит в стор, раздача сборки детям без взрослого | раунд всех девяти с 0 блокеров |

Между воротами — проверка агентами зон изменения по диффу. Блокер — только вред ребёнку, утечка
данных, неработающий продукт или нарушение ABA-процедуры. Стилистические гарды корпуса —
предупреждения, новых жёстких не добавляем (№122). SCREENS.md и ABA.md заморожены до плейтеста (№123).

## Субагенты

В проекте есть девять специализированных субагентов в `.claude/agents/`. У каждого своя зона
ответственности и явно очерченная не-своя зона, чтобы они не дублировали друг друга.

| Агент | Его зона | Не его зона |
|---|---|---|
| **backend-auditor** | Архитектура монорепо, качество кода, схема БД и миграции, API-роуты прокси, достаточность покрытия тестами, деплой/CI, масштабируемость | Приватность детских данных → `child-privacy-compliance`. Политики сторов → `release-readiness-auditor`. Написание и прогон тестов → `qa-engineer` |
| **curriculum-content-reviewer** | Качество заданий, уроков и диалогов Tali: ясность, вовлечённость, прогрессия сложности, разнообразие форматов, соответствие возрастной полосе | ABA-методология → `aba-pedagogy-specialist`. Перевод и локализация → `localization-qa`. Удобство интерфейса → `child-ux-specialist` |
| **design-lead** | Визуальное направление: палитра, типографика, дизайн-система и токены темы, визуальная айдентика Tali, иллюстрации, тёмная/calm тема | Usability и взаимодействие для детей → `child-ux-specialist`. Качество текстов заданий → `curriculum-content-reviewer` |
| **aba-pedagogy-specialist** | Соответствие ABA: task analysis, иерархия подсказок least-to-most и их затухание, режимы подкрепления и токен-экономика, генерализация, корректность сбора данных о прогрессе | Общее качество контента → `curriculum-content-reviewer`. Перевод ABA-текстов → `localization-qa`. Приватность данных → `child-privacy-compliance` |
| **child-privacy-compliance** | Данные детей: consent-флоу и возрастной гейт, минимизация, что уходит во внешние сервисы, разграничение доступа (RLS под углом «не увидит ли посторонний чужого ребёнка»), safety-блоклисты, право на удаление | Общая архитектура и производительность БД → `backend-auditor`. Требования и формы сторов → `release-readiness-auditor` |
| **release-readiness-auditor** | Публикация в App Store и Google Play для детских категорий: age rating, Kids Category / Families policy, реклама, IAP, Data Safety и App Privacy, submission checklist. Проверяет актуальные политики веб-поиском | Внутренняя реализация защиты данных → `child-privacy-compliance`. Техническое качество бэкенда → `backend-auditor`. Прогон сборки → `qa-engineer` |
| **child-ux-specialist** | Usability для детей 4–10: размеры зон нажатия под мелкую моторику, когнитивная нагрузка на экран, навигация без чтения, длина и темп сессии, понятность обратной связи, доступность | Визуальный стиль, цвет, шрифты → `design-lead`. Содержательная ценность заданий → `curriculum-content-reviewer` |
| **localization-qa** | Консистентность ru / en / ky: полнота перевода, единство тона Tali на всех языках, терминология, плюрализация, культурная адаптация, длина строк под вёрстку | Педагогическая ценность контента в оригинале → `curriculum-content-reviewer`. Сама ABA-процедура → `aba-pedagogy-specialist` |
| **qa-engineer** | Функциональное тестирование: написание и прогон unit/integration/e2e, воспроизведение багов, регрессия перед релизом, кросс-платформенная проверка iOS/Android, smoke-чеклист перед EAS-сборкой, починка CI | Статическая оценка качества кода и архитектуры → `backend-auditor`. Политики сторов → `release-readiness-auditor`. Удобство для ребёнка → `child-ux-specialist` |

## Правило маршрутизации

**Если задача попадает в зону одного из агентов — вызывай агента, а не выполняй её основным потоком.**

Это относится и к задачам, которые выглядят маленькими: «глянь, нормально ли это задание»,
«проверь один RLS-полиси», «почему падает тест». Специализированный агент проходит свой
чеклист целиком и находит то, что беглый ответ пропустит.

Основной поток берёт работу на себя только когда:

- задача не попадает ни в одну зону (обычная правка кода по конкретному ТЗ, рефакторинг по
  указанию, ответ на вопрос «где лежит X»);
- пользователь явно попросил сделать это без субагентов;
- нужно применить правки, которые агент выдал текстом (агенты `backend-auditor`,
  `curriculum-content-reviewer`, `aba-pedagogy-specialist`, `child-privacy-compliance`,
  `release-readiness-auditor`, `child-ux-specialist`, `localization-qa` — read-only и не редактируют
  файлы; Edit/Write есть только у `design-lead` и `qa-engineer`).

Результат работы агента пересказывай пользователю: вывод субагента он не видит.

## Составные задачи: несколько агентов параллельно

Когда запрос покрывает несколько зон — запускай агентов **одним сообщением, параллельно**, а потом
сводя их находки в единый список с общими приоритетами.

| Запрос | Агенты параллельно |
|---|---|
| «Проверь проект перед релизом» | `backend-auditor` + `child-privacy-compliance` + `release-readiness-auditor` + `qa-engineer` |
| «Готов ли новый мир к выпуску» | `curriculum-content-reviewer` + `aba-pedagogy-specialist` + `localization-qa` |
| «Полный аудит приложения» | все девять (дизайн и UX — по правилу последовательности ниже) |
| «Проверь ABA-режим целиком» | `aba-pedagogy-specialist` + `child-privacy-compliance` (данные о ребёнке в live-сессии) + `qa-engineer` (тесты ABA-сторов) |
| «Мы добавили чат с ИИ для детей — всё ли в порядке» | `child-privacy-compliance` + `release-readiness-auditor` + `backend-auditor` |
| «Добавили кыргызский в новый мир» | `localization-qa` + `curriculum-content-reviewer` |
| «CI красный и непонятно почему» | `qa-engineer` (ведущий) + `backend-auditor`, если причина в архитектуре сборки |

Правила сведения результатов:

- находки с пересечением зон не дублируй — оставляй формулировку того агента, чья зона основная;
- приоритеты выстраивай сквозные: блокер приватности выше, чем блокер производительности;
- если два агента противоречат друг другу, покажи противоречие пользователю, а не выбирай молча.

## Последовательные вызовы: дизайн и UX

**При оценке или разработке нового урока `design-lead` и `child-ux-specialist` вызываются
последовательно, а не параллельно.**

1. Сначала **`design-lead`** — задаёт визуальное направление: палитра, типографика, иерархия
   экрана, айдентика Tali, поведение в calm/focus и тёмной теме.
2. Затем **`child-ux-specialist`** — получает это направление на вход и проверяет его по детским
   критериям: пройдут ли предложенные размеры зон нажатия, не перегружен ли экран, работает ли
   навигация без чтения, укладывается ли темп в лимит внимания возрастной полосы.

Почему именно так: usability нельзя проверить у того, чего ещё нет, а параллельный запуск даёт два
несогласованных набора рекомендаций — визуальный агент предложит плотную сетку, а UX-агент
раскритикует её, не зная замысла. Если `child-ux-specialist` находит блокер, возвращайся к
`design-lead` с конкретным ограничением («минимум 60×60 pt на вариант ответа») и прогоняй цикл
заново, а не правь дизайн сам.

Обратный порядок — когда задача формулируется как «почему ребёнку неудобно», а не «сделай новый
дизайн»: тогда первым идёт `child-ux-specialist`, и `design-lead` подключается только если
выясняется, что проблема в визуальном языке.

## Скиллы

Агенты проверяют, скиллы производят: скилл — пошаговый конвейер в `.claude/skills/`,
по которому работа каждый раз делается одинаково и сразу проходит гарды. Результат
скилла затем проверяет агент своей зоны.

### Установленные

| Скилл | Когда |
|---|---|
| `lesson-author` | написать уроки и задания для темы сетки в `src/content/` |
| `textbook-ingest` | разобрать стандарт, учебник или программу в заметки по темам |
| `rebuild-log` | записать решение, закрыть или добавить шаг, обновить вход в `REBUILD.md` и таблицу `AUDIT.md` |
| `db-migration` | новая миграция, таблица, колонка, функция, триггер, RLS-политика — и тесты в PGlite |
| `tali-lines` | реплики Tali по ситуациям, правила подстановок, сюжетные события, `companionSituations.ts` |
| `format-screen` | экран одного формата задания (`choose` / `point` / `match` / `order` / `group` / `build`): черновик ответа, компонент, состояния плиток, тесты механики |

Облачные сессии ставят зависимости хуком `.claude/hooks/session-start.sh`, поэтому
гарды (`corpus.test.ts`, `registry.test.ts`, `npm run test:db`) запускаются сразу.

### Отложенные — предложить, когда до них дошло дело

**Правило.** Если пользователь упоминает работу из левой колонки или начинает её,
до начала работы одной-двумя фразами скажи, что для этого запланирован скилл, чем он
поможет, и предложи добавить его сейчас. Предлагай каждый скилл один раз за разговор;
отказ не повод не делать задачу. Что каждый скилл должен уметь —
`.claude/SKILLS_BACKLOG.md`. После добавления перенеси строку в «Установленные» и
удали раздел из бэклога.

| Работа | Скилл |
|---|---|
| новые картинки, иконки, предметы, жители; Recraft, Nano Banana, `registry.ts` | `asset-pipeline` |
| новый роут `/api/*` в прокси | `proxy-route` |
| озвучка корпуса, TTS, ElevenLabs | `voice-build` |
| EAS-сборка, обновление Expo SDK, нативные модули, `app.json` | внешний: Expo Skills |
| подключение облачного Supabase, накат миграций на ветку | внешний: Supabase Agent Skills |
| анимация Tali кодом, Reanimated, производительность карты | внешний: Vercel `react-native-skills` |

## Соглашения по коду

- Слои: `src/domain/` — чистая логика без I/O; `src/services/local/` — данные на устройстве.
  Итоги урока и ABA пишутся только через `services/local/commit.ts` (одна транзакция); журналы —
  только дописывание. Прямые вызовы Supabase из экранов не добавляем.
- Фоновая синхронизация идёт через `syncWithRetry` (`src/services/syncStatus.ts`), а не через
  голый `.catch(() => {})`.
- Все пользовательские строки — через `t()` и локали `ru` / `en` / `ky`; хардкод текста не
  добавляем.
- Цвета и размеры — через токены `src/design/` (`tokens.ts`, `abaTokens.ts`, `parentTokens.ts`), а не хардкодом в стилях.
- Ключи провайдеров (DeepSeek, ElevenLabs, Hugging Face) никогда не попадают в мобильное
  приложение — только через прокси.
- Каждый новый роут прокси: Supabase JWT + Zod-схема на тело + rate limit.
- Всё, что касается конкретного ребёнка, прокси делает **от имени пользователя**
  (`supabaseAsUser(jwt)` из `src/lib/supabaseUser.ts`), а не через `supabaseAdmin`:
  service-role обходит RLS, и `childId` из тела запроса становится единственной
  «проверкой» доступа.
- Согласие родителя в роутах проверяется `hasConsent` (`src/lib/consentCheck.ts`) —
  функцией `has_consent` под JWT пользователя: для чужого ребёнка ответ всегда «нет».
  `consent_active` (только `service_role`) — лишь для фоновых заданий без пользователя.
  Права `has_consent` не расширяем.
- Sentry — только в прокси, в мобильном приложении его нет (решение №62: падения — во
  встроенной статистике сторов). В прокси Sentry не получает идентификаторов: без
  `Sentry.setUser`, без `sendDefaultPii`. Иначе после удаления аккаунта в Sentry остаются
  данные, которые оттуда не удалить.
- Разрешения в `app.json` — только под работающую функцию: разрешение без функции —
  причина отказа в сторе. Микрофон вернётся вместе с голосовыми форматами, с текстом,
  который называет, где идёт распознавание.
- Миграции добавляются новым файлом с временной меткой; существующие не редактируем.
